# Phase 4 planning validation (disposable)

**Purpose:** executed evidence for [AURA-PHASE-4-PLAN.md](../../AURA-PHASE-4-PLAN.md). These artifacts are **not** application code, **not** real migrations, and are **not** wired into the app, the migration ledger (`supabase/migrations/`) or CI. They exist so the Phase 4 design is proven on a disposable engine before any implementation is authorized.

## Contents

- `proposed/0008_public_storefront.sql` — proposed additive migration: seller suspension overlay + guards, four-eyes extension (suspend **and** restore), confidential-note accessor (`aura.seller_suspension_note`), `aura_public` role with **zero base-table grants**, `ALTER POLICY … TO aura_app` scoping, role-targeted public RLS policies (**complete defense-in-depth: approved seller + no suspension on products/variants/media/attributes/redirects**), **SECURITY DEFINER discovery views** (slug-keyed, no internal ids/seller fields) with **§8 explicit ownership reassignment** to the non-superuser NOBYPASSRLS catalog table owner, isolated `public_rate_limits`, `slug_redirects` + public redirect view, function EXECUTE hygiene.
- `proposed/0009_global_product_slugs.sql` — proposed additive migration: deterministic cross-org slug dedupe (trigger-safe backfill) + global unique index.
- `proposed/rollback_0009_global_product_slugs.sql` — reviewed rollback (restores originals, removes only collision redirects, aborts on drift).
- `validate.ts` — replays the real `0001`–`0007` ledger on fresh in-memory PGlite, applies the proposals, builds multi-tenant fixtures through the real guarded paths (incl. an unapproved-seller fixture), and asserts **97 checks** (roles/zero-base-grants/EXECUTE/definer-view + **ownership catalogs 1.16–1.19** + **ownership-procedure proofs 1.20–1.24** [executor membership enables reassignment / non-member denied / member-of-owner RLS bypass / note-accessor helper EXECUTE necessary+sufficient / public login view-only], anonymous reads + negative paths + exact API list SQL + **search/attribute/sort 2.16–2.20**, **defense-in-depth simulated-grant negatives 2.21–2.29**, suspension lifecycle/four-eyes/freeze/restore/note-confidentiality, slug backfill/redirects/rollback/drift, limiter isolation, double replay). The deployment runbook these proofs support is [../../AURA-PHASE-4-DATABASE-OWNERSHIP-PROCEDURE.md](../../AURA-PHASE-4-DATABASE-OWNERSHIP-PROCEDURE.md).
- `cursor.ts` — reference implementation of the corrected cursor contract: `base64url(payload).base64url(HMAC-SHA256)`; payload `{v:1, b:sha256(binding), k:[key0,key1]}`; keyset `[approvedAt, slug]` (newest) / `[title, slug]` (title) — never an internal id; binding = route + search + category + sorted attributes + sort + limit; `timingSafeEqual`; `InvalidCursor` on any tamper/mismatch/malformed input. `node:crypto` only.
- `cursor.test.ts` — **16 executable tests**: A1–A12 contract (round-trip, tampered payload/signature, wrong secret, mismatched route/search/category/attribute/sort/limit, attribute-order independence, malformed shapes) + B1–B4 PGlite pagination (full coverage with no duplicates/omissions at limits 3/2/3 for newest/title/search; cross-sort cursor rejection).
- `probe-app.ts` — 9 checks against the real Express app using the repository's disposable-DB harness: confirms the `no-store` mount-order defect on `/api/v1`, anonymous GET/CSRF compatibility, cross-site mutation refusal, uniform API 404, seller auth requirement.
- `results/` — executed logs: `sql-validation.log` (**97/97**), `cursor-tests.log` (**16/16**, reported separately per owner request), `app-probe.log` (9/9), `browser-baseline.log` (3/3, sandbox NSS workaround, preserved unchanged).

## Findings that changed the design

1. Public reads initially failed with `permission denied for function is_active_member`: Phase 2/3 helper-calling policies target PUBLIC (all roles). Fix: `ALTER POLICY … TO aura_app` (never grant helper EXECUTE to the public role). Check 1.12.
2. `catalogue_suspension_guard` referenced `old.status` on child tables (SQL `AND` does not guarantee short-circuit). Fix: nested IFs. Check 3.17.
3. Suspension trigger ordering: `seller_profiles_0_suspension_guard` fires first so mixed edits fail as `suspension_must_be_atomic`; four-eyes denial for dual-role admins still comes from `review_separation_guard`. Checks 3.1/3.11/3.13/3.20.
4. App probe confirmed `/api/v1` responses currently lack `Cache-Control: no-store` (middleware mounted after the v1 routers). Phase 4 reorders the mount. Probe A.3.
5. **Owner correction (2026-11-27):** public reads moved from `security_invoker` + column grants to **zero-base-grant SECURITY DEFINER discovery views** (D-02 — column grants cannot hide internal join/predicate ids), public seller storefronts removed (D-01), and the suspension note made confidential via column grant + the `aura.seller_suspension_note` accessor with redacted audit detail (D-03). Checks 1.3–1.5/1.14/1.15, 2.6–2.8, 3.5–3.10.
6. **Second owner review round (2026-11-27):** four corrections applied — (a) search/filter/sort restored to Phase 4 scope and proven on the definer views with no new grants (2.16–2.20; UX choices registered as D-23/D-24/D-25, not decided); (b) cursor keyset made sort-consistent (`[approvedAt, slug]`/`[title, slug]`, previously the inconsistent `[approvedAtISO, id]`) and bound to route/search/filters/sort/limit, with 16 executable tests; (c) definer ownership made explicit (0008 §8 reassigns views to the catalog owner; catalog assertions 1.16–1.19 prove non-superuser/NOBYPASSRLS ownership, definer mode and effective grants); (d) defense-in-depth public policies completed with approved-seller + no-suspension predicates, proven by temporarily granting base SELECT to `aura_public` and asserting suspended/unapproved sellers stay hidden across all four tables, then revoking (2.21–2.29).
7. **Final-preparation revision (2026-11-27):** added the standalone [database ownership & migration prerequisites runbook](../../AURA-PHASE-4-DATABASE-OWNERSHIP-PROCEDURE.md) (catalog-owner creation/attributes, base-table ownership, executor privileges + membership, SECURITY DEFINER view ownership, NOSUPERUSER/NOBYPASSRLS verification, grants/default privileges, migration order, rollback) and five executable proofs (1.20–1.24). Key executed findings: a non-superuser **member** of the table owner bypasses catalog RLS (ENABLE not FORCE) and can reassign ownership, a **non-member** is denied; the suspension-note accessor's owner needs explicit helper EXECUTE (`is_active_member`/`is_platform_admin` are not PUBLIC-executable); a public LOGIN inheriting `aura_public` gets view-only SELECT. D-23/D-24/D-25 recorded as proposed defaults **awaiting owner confirmation, not approved**.
8. **Browser baseline in this sandbox:** plain `pnpm test:browser` cannot launch Chromium (missing NSS/NSPR). Decompress `@sparticuz/chromium` `bin/al2023.tar.br` to `/tmp/al2023` and run with `LD_LIBRARY_PATH=/tmp/al2023/lib` → 3/3. Sandbox setup only; no repository file changed. Hosted CI (`google-chrome`) remains the authoritative browser gate.
