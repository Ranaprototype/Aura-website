## Final-review fixes (this session, all uncommitted)

1. **Public limiter aligned to approved plan §3.4** (`server/modules/storefront/limits.ts`,
   `server/config.ts`): the bucket is now a hashed client IP (`sf:<sha256(ip)[:32]>`,
   never the raw address); the default budget is the approved **240/min**; windows
   older than one hour are pruned opportunistically via the public pool (throttled
   to once per minute per instance); and a limiter query failure falls back to a
   bounded per-instance in-memory counter with the **same** limit plus a logged
   warning — never unlimited, never a full browsing outage. Covered by
   `tests/storefront-limits.test.ts` (5 tests: hashing, increment/deny, pruning,
   fallback budget + warning, per-IP isolation).
2. **Marketplace browser flake fixed** (`tests/browser-marketplace.mjs`,
   `client/src/pages/MarketplacePage.tsx`): in-page filter transitions asserted
   against a stale grid (a bare `waitFor()` resolved before React re-rendered,
   intermittently reading 0 cards — reproduced 2/3 failures). The test now waits
   for the expected grid state via a retrying `waitForFunction`, and the page
   gained a request-sequence guard so a slow stale fetch can never overwrite a
   newer query result. Verified with **5 consecutive passing** storefront runs.

## Security posture proven (PGlite semantics)
- Migrations `0008`/`0009` apply twice cleanly (replay-safe). `aura_catalog_owner`
  is `NOSUPERUSER`/`NOBYPASSRLS`/`NOLOGIN` and owns the five `public_*` definer
  views; `aura_public` has SELECT on the views only — `has_table_privilege` on
  `aura.products` is **false**, on `aura.public_products` **true**.
- Public reads run on a separate pool that never binds a principal; absent or
  unreachable pool ⇒ `503 storefront_unavailable`, never an app-pool fallback.
- Anonymous payloads carry only the D-02 slug-keyed allowlist — no internal
  org/product/revision ids, no seller identity, no SKU.
- Suspension is platform-admin + four-eyes + atomic + noted; the confidential
  note is reachable only via the role-checked definer accessor and is excluded
  from the member-readable audit trail.
